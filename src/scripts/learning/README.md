# Локальный аудит учебного пакета (LP-03)

Инструмент запускается только из CLI, не импортирует и не публикует занятия, не исправляет французский текст. Нужны установленные зависимости приложения, PHP с PDO SQLite, intl и mbstring; новых пакетов нет. Веб-приложение не зависит от этого инструмента и наличия learning/.

Из `src` при доступном локальном PHP:

~~~sh
php scripts/learning/audit-packages.php --package=../learning/programme/packages/PRE_A1/PRE_A1-U01.v1.json --new-material --output-dir=../learning/programme/editorial/improvement
php scripts/learning/audit-packages.php --map=../learning/programme/map.v1.json --unit=PRE_A1-U05 --unit=A1-U05 --unit=A2-U05 --unit=B1-U05 --new-material --output-dir=../learning/programme/editorial/improvement
~~~

`--package` и `--context` можно повторять. Контекст задаётся в порядке изучения, только предыдущие пакеты; целевой пакет нельзя передавать своим контекстом. Пример для U05 без карты: один `--package=...U05.v1.json` и четыре `--context=...U01.v1.json` ... `--context=...U04.v1.json`.

`--map` читает только `package_path` из активной карты. С `--unit` выбираются указанные темы и необходимые предыдущие темы того же уровня, по order; будущие/посторонние пакеты не читаются. Без `--unit` проверяются все перечисленные в карте пакеты; это явный полный аудит, не рекурсивный поиск JSON. Не сочетать `--map` с `--context`. Если прошлый контекст неполон или невалиден, сначала исправить выбор контекста: инструмент не создаёт фиктивные заглушки зависимостей.

Каждый предыдущий пакет проходит каноническую проверку и заносится только во временную SQLite для разрешения ссылок следующего. У каждого целевого пакета своя транзакция с rollback; целевой материал и будущие темы не становятся предшествующим контекстом другого аудита. Перед bootstrap принудительно выставлены testing, SQLite :memory:, пустой DB_URL, array cache/session и sync queue; путь к config cache заменён на заведомо отсутствующий. До migrate проверяется изоляция. Рабочая БД и её миграции не используются.

Выходной файл — `<имя-пакета-без-json>.pedagogy.json`. По умолчанию это `learning/programme/editorial/improvement` относительно настроенного content_path; лучше задавать `--output-dir` явно. Каталог packages, пересечение с входами и одинаковые имена выходов запрещены. Запись атомарная; SHA-256 входов проверяются до выдачи. Отчёт включает канонические errors/warnings, отдельные педагогические warnings, путь/отпечаток источника и каждого пакета контекста, параметры изоляции. При невалидной структуре педагогические эвристики не запускаются: ошибка не превращается в положительное заключение.

Коды завершения: **0** — каноническая проверка прошла, педагогические предупреждения могут оставаться; **1** — целевой пакет не прошёл канонический валидатор (отчёт сохранён); **2** — ошибка входа/контекста/изоляции/выдачи (см. audit_error в stderr). При нескольких целях с кодом 1 остальные всё равно проверяются. Отсутствие предупреждений не равно одобрению преподавателя.

## Что проверяется

Канонический `SessionPackageValidator` отвечает за схему, ссылки целей/словаря/assessed_vocabulary, before_task_id, корректные пары и полные порядки токенов, данные транскрипций. Отсутствующее аудио для listening и варианты словарного повторения могут быть предупреждениями канонического валидатора — они не теряются в отчёте.

Эвристики дополняют его:

- `checkpoint_source_reuse` — дословный источник чтения/аудирования контроля уже встречался в обычном задании того же уровня. Для совпадений не более четырёх токенов отдельный `common_short_source_reuse`, confidence=low_short_phrase: короткая общеупотребительная реплика может законно повторяться. Более длинное совпадение тоже требует редакторского решения.
- `repeated_question` — совпадают тип, условие и материал карточек/вариантов после нормализации. Служебные ID/транскрипции и порядок полей JSON не влияют; порядок карточек/вариантов сохраняется. Повторение ради извлечения из памяти может быть полезным.
- `correct_option_length_cue` — правильный вариант минимум в 1,5 раза длиннее самого длинного отвлекающего и разница от трёх токенов. Это эвристика подсказки формой, не предел длины источника и не языковая норма.
- `correct_option_position_bias` — от пяти вопросов с выбором, не менее 80% правильных вариантов на одной авторской позиции. Реальное перемешивание в плеере может уменьшать риск. `repeated_correct_answer` — один правильный текст от трёх вопросов в занятии.
- `no_new_source_context` — все французские источники занятия дословно встречались ранее. Это не анализ нового смысла/ситуации: новый источник ещё не доказывает перенос, прежний источник не исключает новую задачу.
- `assessment_without_prior_intro_link` / `checkpoint_without_prior_intro_link` — оцениваемый ключ не связан с более ранней вводной карточкой в переданном контексте. Список vocabulary не считается доказательством введения. Ссылка тоже не доказывает объяснение или усвоение. Карта автоматически берёт только предыдущие темы текущего уровня; входные знания из нижних уровней и эквивалентная подготовка ученика должны проверяться редактором отдельно. Это отличается от глобальной последовательности PRE_A1→B1 в coverage.json LP-01.
- `missing_review_variant` — у вводимого/оцениваемого выражения нет review_items. `review_context_not_demonstrated` — не найден отличный от заданий занятия французский источник в вариантах повторения; переводной вопрос может проверять значение, но не демонстрирует применение. Само наличие другого текста не доказывает нового контекста.
- `listening_source_missing` — отсутствует текст аудио. Для новых материалов `--new-material` выдаёт `typed_input_in_new_material` для short_answer/fill_blank text, в том числе внутри review_items. Без флага это `legacy_typed_input`: старые типы не удаляются из поддержки.

Сравнение нормализует Unicode NFC, регистр, апостроф и пробелы, но не изменяет вход. Подсчёт токенов сохраняет внутренние апострофы/дефисы. Нет лемматизации, проверки естественности, соответствия CEFR, качества браузерного голоса, фактического времени или эффективности обучения. Ошибочные и пропущенные срабатывания возможны; все пороги описывают риск, а не обязательную квоту.

## Текущий Docker без mount learning

На 06.11.2026 фактический `docker inspect afr-php` показывает bind mount только src и php.ini: mount learning из compose ещё не применён. `/var/www/learning` содержит отдельную копию; нельзя молча считать её актуальным банком хоста. Контейнер ради аудита не пересоздаётся. Копируйте свежий снимок нужных активных пакетов в `/tmp`, затем возвращайте только отчёты и сверяйте SHA-256 с хостом. Например, из корня проекта в WSL для одной PRE_A1-U05:

~~~sh
docker exec afr-php mkdir -p /tmp/afr-editorial-snapshot /tmp/afr-editorial-reports
for unit in 01 02 03 04 05; do
  docker cp "learning/programme/packages/PRE_A1/PRE_A1-U${unit}.v1.json" "afr-php:/tmp/afr-editorial-snapshot/PRE_A1-U${unit}.v1.json"
done
docker exec -w /var/www/afr afr-php php scripts/learning/audit-packages.php --package=/tmp/afr-editorial-snapshot/PRE_A1-U05.v1.json --context=/tmp/afr-editorial-snapshot/PRE_A1-U01.v1.json --context=/tmp/afr-editorial-snapshot/PRE_A1-U02.v1.json --context=/tmp/afr-editorial-snapshot/PRE_A1-U03.v1.json --context=/tmp/afr-editorial-snapshot/PRE_A1-U04.v1.json --new-material --output-dir=/tmp/afr-editorial-reports
docker cp afr-php:/tmp/afr-editorial-reports/PRE_A1-U05.v1.pedagogy.json learning/programme/editorial/improvement/
~~~

Поля sha256/source/context относятся к проверенному снимку. Сверка `sha256sum` исходного файла на хосте с sha256 отчёта обязательна перед использованием замечаний; при изменении материала отчёт устаревает. В запуске LP-03 использован снимок карты и ровно 20 активных пакетов U01–U05 четырёх уровней, затем сверены отпечатки источников и всех контекстов, отчёты возвращены в локальный improvement.

## Проверки инструмента

~~~sh
php artisan test --filter=PracticePedagogyAudit
~~~

Тесты подготавливают дубли, длинный правильный ответ, однотипный порядок/текст ответа, недостающие варианты повторения, ввод текста, отсутствие аудио/транскрипции, неверные ссылки/пары/порядки карточек и повреждённый JSON. Отдельный процесс проверяется с production/mysql/DB_URL и заведомо недопустимым кэшем конфигурации: он обязан использовать только testing/SQLite :memory:. Также проверяются неизменность входов, ограниченный выбор карты, различение коротких совпадений и отказ записи в packages.
